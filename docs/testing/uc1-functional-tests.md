# UC1 Functional Test Cases — Product Relationships Page

**Feature under test:** UC1 Product Relationships page (`#/uc1`)
**Test type:** Manual functional (black-box) testing through the browser
**Environment:** Chrome, Vite dev server at http://localhost:5173, Supabase project with UC1 output
**Last updated:** 2026-10-19, for the business-language page (US1.13) and the engine that mines hospital requests

Unit tests check the engine functions on their own (see `uc1-unit-tests.md`). These functional tests check
what a user sees and does on the page, from end to end, using the real data in the database.
How each user story's acceptance criteria are covered is shown in `uc1-traceability.md`.

> **Last run: 2026-10-19 — 29 Pass, 1 Fail (FT-013), 1 Blocked (FT-027).** Run headless in Chromium (Playwright)
> against the local dev server and the live Supabase data, after the page was relabelled for business users (US1.13)
> and the database was rebuilt on 2026-10-17. Each expected result was checked on the page and, for FT-015, 016, 017
> and 029, against `productrelationship`. A screenshot was taken for every case.
> Evidence (screenshots, exported CSV, test script): [evidence/uc1-2026-10-19](evidence/uc1-2026-10-19/README.md).

## What changed on the page (old label → current label)

| Area | Old label | Current label |
|---|---|---|
| KPI cards | Unique Pairs · Strong Relationships · Co-pick Relationships · Total Orders | Unique Product Combination · Strong Product Combination · Total Product Combination · Orders Analysed |
| Table columns | Antecedents · Consequent · Itemset · Support · Confidence · Lift · Strength | Primary Product · Frequently Bought With · Bundle Size · Popularity · Reliability · Relationship pattern · Suggestion |
| Strength values | Strong · Moderate · Weak | Best Bundle · Recommended Bundle · Consider Bundle |
| Filters | Strength · Itemset ("3-item", "All itemset sizes") · "Search for SKU" | Suggestion · Bundle size ("3 products", "All bundle sizes") · "Search for product" |
| Warehouse picker | "WH001 · …" · "Select all Subsidiary Hospitals" | "Product combination shared across all warehouse" · "Select all Subsidiary Warehouse" |
| Graph | Network Graph · sliders Min support / Min confidence / Min lift | Product Clusters · sliders Popular Product Combination / Reliable Product Combination |
| Number format | Support to 3 decimal places | Popularity as a % to 1 decimal place |

## Common pre-conditions

1. `productrelationship` holds rules for WH001 and every subsidiary. The scheduled workflow runs the engine monthly;
   to run it by hand: `python -m engines.uc1.arm_jeremiahVer` (needs hospital requests in `stocktransfer`).
2. Start the frontend with `npm run dev`.
3. Open http://localhost:5173/#/uc1, or click **Product Relationships** in the sidebar.

To check the expected results of the data-accuracy cases (FT-015, FT-016), query Supabase directly, for example:
`SELECT strength, count(*) FROM productrelationship WHERE warehouseid = 'WH001' GROUP BY strength;`

Reference data on 2026-10-19 (refresh after each engine run): every warehouse (WH001–WH006) has 98 rules:
61 with 2 products, 33 with 3 and 4 with 4. WH001 has 35 Strong rules. MED0057 is *Ventolin Salbutamol Inhaler
Original 100mg*. The pair MED0101–MED0109 appears at both WH002 and WH003.
